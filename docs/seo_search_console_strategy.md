# BÐ-Studio Google Search Console 關鍵字策略與站點描述優化計畫

**適用站點：** `https://larrylai777.github.io/bd-studio/`  
**核心作品：** 《第九次出生》  
**核心節目：** 比爸說播客｜BÐ Tell  
**計畫目的：** 讓搜尋引擎、讀者與未來合作方能清楚理解：BÐ-Studio 是以《第九次出生》為核心、持續向小說、聲音與影像延伸的原創故事工作室。

## 一、先釐清：Google Search Console 不是「填關鍵字」的地方

Google Search Console 的工作是**驗證網站、提交 sitemap、檢查索引狀態，並觀察使用者實際輸入哪些查詢後找到網站**；它不是可手動設定排名關鍵字的廣告後台。真正應被優化的是頁面本身的主題、標題、主要標題、內文、內部連結與中繼描述。Search Console 的價值在於把實際的曝光、點擊、點閱率與平均排序回饋給內容決策。[1]

因此，BÐ-Studio 的策略不應是把大量詞彙塞進描述或標題，而是先建立一個清晰的查詢地圖：每一類搜尋意圖都要有一個最合適的落地頁，而每個落地頁只承擔一個明確的主題。Google 建議每頁使用描述清楚且不重複的標題，並避免堆疊或重複關鍵字。[2]

> 核心判斷原則：**讀者搜尋的是作品、題材、收聽方式或創作背景；BÐ-Studio 的每個頁面要回答其中一個問題，而不是同時回答所有問題。**

## 二、BÐ-Studio 的搜尋定位

### 2.1 品牌定位句

建議在首頁、工作室頁、簡介頁與對外社群簡介一致使用下列句子：

> **BÐ-Studio 是以原創科幻小說《第九次出生》為起點，發展播客、影集、電影與實體企劃的跨媒介故事工作室。**

這句話同時包含品牌名、作品名、原創小說、科幻、播客、影集與電影等可被理解的實體語意，但仍維持自然敘述。它不應在每一段重複，而應作為首頁首段、工作室頁首段與媒體介紹中的固定定位。

### 2.2 優先排序

網站初期不應把重點放在競爭極高且過於寬泛的詞，例如「科幻小說」、「小說」或「Podcast」。這些詞缺乏明確意圖，且大型平台、媒體與既有作者會占據大部分結果。BÐ-Studio 應先用**可被獨占的品牌與作品詞**建立索引，再用作品的具體題材詞擴張自然搜尋觸及。

| 優先級 | 查詢群 | 搜尋者意圖 | 主落地頁 | 成功訊號 |
|---|---|---|---|---|
| P0 | 品牌詞、作品精確詞 | 找到正確官方來源 | 首頁、原作頁 | 品牌詞曝光與高 CTR |
| P1 | 作品＋閱讀、作品＋章節 | 直接開始閱讀 | 原作頁、閱讀站 | 閱讀站點擊、章節瀏覽 |

## 三、關鍵字群組與頁面對應

### 3.1 P0：品牌與作品防守詞

這是網站最先必須拿到的搜尋空間。即使搜尋量不高，也最接近明確的讀者、聽眾或合作對象。請在 Search Console 的「成效」報表中優先檢視下列詞及其繁簡、空格、大小寫或符號變形：

* `BÐ-Studio`、`BD Studio`、`BÐ Studio`、`比爸工作室`
* `第九次出生`、`第九次出生小說`、`第九次出生 閱讀`
* `比爸說播客`、`比爸說 BÐ Tell`、`BD Tell`
* `林澈`、`冥河陣列`、`火星 記憶清除`

其中「第九次出生」應由原作頁擔任官方敘事入口，而閱讀站則承接「第九次出生 閱讀」與章節型意圖。兩站都必須以清楚的雙向文字連結相連：官網說明作品與世界觀；閱讀站提供正文與章節導覽。這能降低搜尋者落到單一頁面後找不到下一步的機率。

### 3.2 P1：高意圖的閱讀與收聽詞

這一群會帶來更接近轉換的訪客。原作頁應明確用自然語句寫出「閱讀《第九次出生》」、「原創科幻小說連載」與「記憶輪迴故事」；播客頁則應使用「收聽比爸說播客」、「《第九次出生》故事播客」與「Apple Podcasts」等語句。

推薦觀察的查詢包括：

* `第九次出生 線上閱讀`、`第九次出生 小說連載`、`第九次出生 章節`
* `第九次出生 podcast`、`第九次出生 播客`、`比爸說 收聽`
* `科幻小說 podcast`、`原創故事 podcast`、`中文科幻故事`

這些詞不能只存在於 meta description。原作頁的首段、封面連結附近、閱讀 CTA 與播客頁的嵌入播放器上方，都應使用讀者看得懂的文字說明，讓主要內容、主標題與連結文字相互一致。[2]

### 3.3 P2：題材探索詞

題材詞是非品牌流量的主要來源，但必須由具有實際內容深度的頁面承接。建議把下列詞分配給原作頁與製作日誌，不要全部堆在首頁：

* `記憶輪迴小說`、`記憶被清除的小說`、`前世記憶科幻`
* `火星科幻小說`、`未來火星故事`、`華文科幻懸疑`
* `原創科幻小說推薦`、`台灣原創小說`、`中文科幻小說`
* `世界觀設定`、`科幻小說角色設定`、`跨媒介故事創作`

為了讓這些詞有排名條件，建議製作日誌逐步新增可索引的內容頁，例如〈冥河陣列：為何火星社會必須清除前世記憶？〉、〈林澈與第九次人生：角色設定筆記〉或〈從小說到聲音：如何把世界觀轉成播客腳本〉。這些頁面必須提供實質內容，而不是只有宣傳段落。

### 3.4 P3：產業與合作詞

此群主要服務對原創 IP、影集、電影開發與跨媒介敘事有興趣的讀者或合作方。建議僅在工作室、影集、電影與製作日誌頁使用：

* `原創 IP 開發`、`跨媒介敘事`、`小說影集改編`
* `小說電影企劃`、`台灣原創影集企劃`、`世界觀開發`
* `故事 IP 工作室`、`原創內容開發`

這類詞的曝光未必很快，但能建立 BÐ-Studio 的專業類別。關鍵是不要把尚未實現的合作、製作規模或上映時程寫成既成事實；頁面應以「企劃」、「開發中」或「製作日誌」等準確狀態表達。

## 四、不要主動追逐的詞

請避免在 title、description 或內文中主動把作品與不相關的熱門作品、作者或平台綁定，例如以「像某某大作」或「某部作品風格」取得點擊。這會讓到站期待與實際內容不一致，也可能把搜尋意圖導向錯誤的競品比較。也不建議使用與真實內容不符的「免費全文」、「完結」、「有聲書」或「動畫」等詞；若將來確實推出對應內容，再建立專屬落地頁即可。

## 五、Search Console 初期查詢篩選方式

網站剛提交 sitemap 後，先以 **28 天**為一個觀察單位，不要在資料量太少時每日改標題。Google 建議以 Search Console 監測查詢、頁面與國家等表現，也建議在內容異動後定期查看索引與穩定度。[1]

第一次檢查時，先在「成效 → 搜尋結果」依序建立下列篩選：

1. **查詢包含「第九次出生」**：確認原作頁是否成為官方主入口。
2. **查詢包含「比爸說」或「BÐ Tell」**：確認播客頁與 Apple Podcasts 導流是否開始累積。
3. **頁面包含 `/original/`**：檢視作品頁的曝光、平均排序與 CTR。
4. **頁面包含 `/podcast/`**：檢視收聽意圖是否帶來曝光。
5. **非品牌詞**：排除「第九次出生」、「BÐ」、「比爸說」後，找出 Google 已經試探展示的題材詞。

接下來的頁面描述優化與 90 天檢查節奏，將在下一節完成。

## 七、Google Search Console 實際操作清單

### 7.1 一次性設定

1. 新增 **網址前置字元資源**：`https://larrylai777.github.io/bd-studio/`。這會與 GitHub Pages 的實際網址完全一致。
2. 以可用的 Google 帳號完成資源驗證。若無法使用 HTML 檔案驗證，則依 Search Console 顯示的可用方式選擇驗證流程。
3. 在「Sitemaps」提交：`https://larrylai777.github.io/bd-studio/sitemap.xml`。站點目前也已在 robots.txt 中宣告此 sitemap。[4]
4. 在「網址檢查」依序檢查首頁、原作頁、播客頁與製作日誌頁。若顯示可建立索引，對近期剛更新的頁面提出一次索引要求即可；不要對同一頁反覆提交。
5. 在「設定」確認主要使用者與權限，避免日後作品夥伴、編輯或代理人誤動資源。

### 7.2 每月 30 分鐘例行檢查

Google 建議至少每月或在內容重大更新後檢查 Search Console；重點不在每日波動，而在看趨勢、索引異常與可重複的內容機會。[1]

| 檢查順序 | 報表或篩選 | 要回答的問題 | 採取動作 |
|---|---|---|---|
| 1 | 成效 → 查詢 | 哪些品牌詞開始有曝光？ | 確認官方原作頁與播客頁是主要落地頁 |
| 2 | 成效 → 頁面 | 哪些頁面已有曝光但 CTR 偏低？ | 先檢查 title、description 是否清楚說明內容與作品名 |
| 3 | 查詢排除品牌詞 | Google 正在用哪些題材詞測試本站？ | 為已出現的題材補一篇實質日誌或 FAQ |
| 4 | 網頁索引 | 重要頁面是否被排除或有抓取問題？ | 用網址檢查找出 canonical、noindex 或載入問題 |
| 5 | 資訊主頁與結構化資料報表 | JSON-LD 是否出現警告或錯誤？ | 修正語法或不符合內容現況的欄位 |
| 6 | Core Web Vitals | 圖片或內嵌播放器是否拖慢體驗？ | 壓縮資產、延遲載入非關鍵 iframe、維持可讀版面 |

### 7.3 90 天評估規則

在有足夠資料前，不要因一兩次曝光就改寫所有頁面。以 90 天作為第一個判斷週期：

* 若「第九次出生」相關查詢有曝光、但 CTR 低於其他品牌詞，優先測試更直接的 title，例如把「原創科幻懸疑小說」放在作品名後。
* 若「記憶輪迴小說」、「火星科幻小說」等非品牌詞出現曝光但排序在第 20 名以後，先增加對應的製作日誌或 FAQ，而非只改首頁 description。
* 若播客頁曝光開始增加、但外部收聽點擊弱，將播放器上方文字改為更具體的單集問題句，例如「如果出生代表前世記憶被清除，保有八世記憶的人會成為希望還是災難？」
* 若讀者常搜尋某位角色或某個設定，建立單獨、可長期維護的角色或世界觀頁，而不是把詞彙散落在多個頁面。

## 八、內容優化優先級：先增加可被搜尋的實質內容

現有官網已經建立良好的品牌與媒介架構，但非品牌搜尋流量仍需要能回答明確問題的內容資產。以下排序比單純擴寫首頁更有價值：

1. **原作導讀頁：** 清楚介紹《第九次出生》的閱讀入口、主題、人物與目前連載狀態。
2. **世界觀 FAQ：** 回答「冥河陣列是什麼？」「為何要清除前世記憶？」「第九次出生的火星社會如何運作？」等問題。
3. **播客單集索引：** 每集提供標題、節目摘要、時長、可聽平台與關聯章節，而非只嵌入播放器。
4. **製作日誌：** 每篇鎖定一個創作問題，例如角色、設定、聲音化或影像化，並從首頁、原作頁與播客頁以文字連結導入。
5. **作者或工作室介紹：** 用可驗證、真實的創作背景說明作品的來源與方向，避免補上未確認的獎項、合作或經歷。

這些頁面不必一次完成，但每新增一頁都要先回答三件事：讀者會用什麼詞找到它、頁面提供什麼獨有價值、讀者看完下一步要到哪裡。如此累積的內部連結與主題深度，比反覆更換 meta keyword 更能建立可持續的自然流量。

## 九、執行時不可忽略的限制

Google 有權依查詢和頁面內容自行選擇 title link 與摘要，網站無法保證 SERP 一定完全採用設定的 title 或 meta description。[2] [3] 此外，提交 sitemap 是協助 Google 發現 URL 的訊號，而不是排名或保證收錄；應把它視為索引管理工具，而非流量開關。[4]

因此，此策略的衡量方式應是「品牌與作品詞是否被正確導向」、「非品牌題材詞是否逐步取得曝光」、「重要頁面是否能被索引」，而不是承諾某個字詞在特定日期排名第一。若未來希望做關鍵字量級與競爭度的正式估算，應另外使用 Google Ads Keyword Planner 或具備台灣／繁中資料來源的第三方工具，並把估算結果和 Search Console 的實際查詢資料交叉驗證。
